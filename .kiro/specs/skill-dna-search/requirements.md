# Requirements Document

## Introduction

A backend service that analyzes student code repositories to extract technical skills using Google Gemini Flash, generates semantic embeddings using local SentenceTransformers models, and performs local hybrid search to match students with job descriptions. The system operates entirely locally without cloud vector databases or paid embedding APIs, using scikit-learn for cosine similarity calculations and MongoDB for storage.

## Glossary

- **System**: The Skill DNA & Headhunter Search Backend Service
- **Skill_Engine**: AI-powered code analysis module using Google Gemini Flash for analysis and SentenceTransformers for embeddings
- **Skill_Profile**: A student's verified technical skills with confidence scores and evidence files
- **Skill_Embedding**: A 384-dimensional vector representation of a student's technical capabilities generated by SentenceTransformers
- **Hybrid_Search**: Local in-memory cosine similarity search using scikit-learn without cloud vector databases
- **Repository_Scanner**: Utility script that recursively scans local directories for code files
- **Gemini_Flash**: Google's fast language model for code analysis and skill extraction (respects 5 RPM free tier limit)
- **SentenceTransformers**: Local HuggingFace embedding model (all-MiniLM-L6-v2) for generating 384-dimensional semantic vectors
- **Cosine_Similarity**: Mathematical measure of similarity between two vectors used for matching
- **Job_Description**: Text describing required skills and qualifications for a position
- **Match_Score**: Numerical similarity score (0.0-1.0) indicating how well a student matches a job
- **Candidate_Result**: GraphQL type containing student information and match score for job searches

## Requirements

### Requirement 1: Backend Dependencies Installation

**User Story:** As a developer, I want to install required Python packages, so that the system has all necessary libraries for embeddings and similarity calculations.

#### Acceptance Criteria

1. THE System SHALL include scikit-learn in requirements.txt for cosine similarity calculations
2. THE System SHALL include numpy in requirements.txt for vector mathematics operations
3. THE System SHALL include google-generativeai in requirements.txt for Gemini API integration
4. THE System SHALL include sentence-transformers in requirements.txt for local embedding generation
5. WHEN requirements.txt is updated, THE System SHALL maintain compatibility with existing FastAPI and MongoDB dependencies
6. WHEN dependencies are installed, THE System SHALL verify all packages are compatible with Python 3.8+

### Requirement 2: User Skill Profile Data Model

**User Story:** As a system administrator, I want to extend the User model with skill profile data, so that student technical capabilities can be stored and retrieved.

#### Acceptance Criteria

1. THE System SHALL define a SkillTag model with name, confidence, and evidence_file fields
2. THE System SHALL define a UserSkillProfile model with verified_skills list, skill_embedding vector, and last_scanned timestamp
3. WHEN extending the User model, THE System SHALL add an optional skill_profile field of type UserSkillProfile
4. THE System SHALL ensure skill_embedding is a list of 384 floats matching SentenceTransformers all-MiniLM-L6-v2 output dimensions
5. THE System SHALL use Pydantic BaseModel for all skill-related data structures with proper type validation

### Requirement 3: AI-Powered Code Analysis

**User Story:** As a student, I want my code to be analyzed by AI, so that my technical skills can be automatically extracted and verified.

#### Acceptance Criteria

1. WHEN a code file is provided to the Skill_Engine, THE System SHALL send the content to Gemini Flash API for analysis
2. WHEN Gemini Flash analyzes code, THE System SHALL extract technical concepts including frameworks, libraries, patterns, and languages
3. WHEN code analysis is complete, THE System SHALL return a structured string of technical skills (e.g., "FastAPI, AsyncIO, MongoDB")
4. THE System SHALL handle Gemini Flash API errors gracefully and provide meaningful error messages
5. THE System SHALL optimize prompts for Gemini Flash to focus on concrete technical skills rather than soft skills
6. WHEN analyzing multiple files, THE System SHALL implement a 12-second delay between API calls to respect the 5 RPM free tier limit

### Requirement 4: Semantic Embedding Generation

**User Story:** As a system administrator, I want to generate semantic embeddings for skill profiles, so that students can be matched with jobs using vector similarity.

#### Acceptance Criteria

1. WHEN a skill summary text is provided, THE System SHALL generate embeddings using the local SentenceTransformers all-MiniLM-L6-v2 model
2. WHEN SentenceTransformers processes the text, THE System SHALL return a 384-dimensional float vector
3. THE System SHALL validate that returned embeddings have exactly 384 dimensions
4. THE System SHALL load the SentenceTransformers model once at initialization for efficient reuse
5. THE System SHALL perform embedding generation locally without external API calls or rate limits

### Requirement 5: Local Repository Scanning

**User Story:** As a student, I want to scan my local code repository, so that my skills can be extracted and stored in my profile.

#### Acceptance Criteria

1. WHEN the Repository_Scanner is executed, THE System SHALL accept a target directory path as input
2. WHEN scanning a directory, THE System SHALL recursively traverse all subdirectories to find .py files
3. WHEN Python files are found, THE System SHALL read file contents and send them to Skill_Engine for analysis
4. WHEN all files are analyzed, THE System SHALL aggregate extracted skills into a single summary string
5. THE System SHALL skip binary files, virtual environments, and common ignore patterns (node_modules, __pycache__, .git)

### Requirement 6: Skill Profile Storage and Updates

**User Story:** As a student, I want my skill profile to be saved to MongoDB, so that my capabilities are persistently stored and searchable.

#### Acceptance Criteria

1. WHEN skill analysis is complete, THE System SHALL generate a master embedding from the aggregated skill summary
2. WHEN the master embedding is generated, THE System SHALL update the User document in MongoDB with the new UserSkillProfile
3. WHEN updating the skill profile, THE System SHALL set verified_skills with SkillTag objects containing name, confidence, and evidence_file
4. WHEN the profile is saved, THE System SHALL record the last_scanned timestamp
5. THE System SHALL use standard pymongo for synchronous database operations in the scanning script

### Requirement 7: Hybrid Local Search Implementation

**User Story:** As a recruiter, I want to search for students matching a job description, so that I can find qualified candidates without using cloud vector databases.

#### Acceptance Criteria

1. WHEN a job description is provided, THE System SHALL generate an embedding vector using the local SentenceTransformers model
2. WHEN the job embedding is generated, THE System SHALL retrieve ALL users from MongoDB who have a skill_embedding field
3. WHEN user embeddings are retrieved, THE System SHALL use sklearn.metrics.pairwise.cosine_similarity to compare job vector against all user vectors
4. WHEN similarity scores are calculated, THE System SHALL return the top 5 users with similarity scores greater than 0.6
5. THE System SHALL perform all similarity calculations in-memory without external vector database or API dependencies

### Requirement 8: Candidate Search Service

**User Story:** As a backend developer, I want a recommendation service, so that job matching logic is encapsulated and reusable.

#### Acceptance Criteria

1. THE System SHALL create a find_matching_students function in backend/services/recommendation.py
2. WHEN find_matching_students is called with a job description, THE System SHALL generate a job embedding using the local SentenceTransformers model
3. WHEN searching for candidates, THE System SHALL retrieve user skill embeddings from MongoDB using motor async driver
4. WHEN calculating matches, THE System SHALL return a list of user objects with match_score and verified_skills
5. THE System SHALL handle cases where no users have skill embeddings by returning an empty list

### Requirement 9: GraphQL Candidate Search Query

**User Story:** As a frontend developer, I want a GraphQL query to find candidates, so that I can integrate job matching into the user interface.

#### Acceptance Criteria

1. THE System SHALL add a findCandidates query to the GraphQL schema accepting jobDescription as a String parameter
2. WHEN findCandidates is called, THE System SHALL invoke the recommendation service with the provided job description
3. WHEN candidates are found, THE System SHALL return a list of CandidateResult objects with student information and match scores
4. THE System SHALL define CandidateResult type with fields: id, username, email, match_score, and verified_skills
5. THE System SHALL require authentication for the findCandidates query using existing JWT validation

### Requirement 10: Standalone Scanning Script

**User Story:** As a student, I want to run a command-line script to scan my repository, so that I can update my skill profile without using the API.

#### Acceptance Criteria

1. THE System SHALL create a scan_local_repo.py script in the project root directory
2. WHEN the script is executed, THE System SHALL accept command-line arguments for target directory and user GitHub ID
3. WHEN the script runs, THE System SHALL connect to MongoDB using standard pymongo (not motor)
4. WHEN scanning is complete, THE System SHALL print progress information and confirmation of profile update
5. THE System SHALL be executable via terminal command: python scan_local_repo.py --directory <path> --github-id <id>

### Requirement 11: API Configuration Management

**User Story:** As a system administrator, I want API keys managed through configuration, so that credentials are secure and environment-specific.

#### Acceptance Criteria

1. THE System SHALL add GEMINI_API_KEY to the backend.config module
2. WHEN the Skill_Engine initializes, THE System SHALL load the Gemini API key from backend.config
3. WHEN API keys are missing, THE System SHALL raise clear configuration errors on startup
4. THE System SHALL add GEMINI_API_KEY to .env.example with documentation
5. THE System SHALL never hardcode API keys in source code

### Requirement 12: Error Handling and Validation

**User Story:** As a developer, I want comprehensive error handling, so that the system remains stable when API calls fail or data is invalid.

#### Acceptance Criteria

1. WHEN Gemini API calls fail, THE System SHALL log the error and return meaningful error messages
2. WHEN embedding dimensions are incorrect, THE System SHALL raise validation errors
3. WHEN no code files are found during scanning, THE System SHALL inform the user and exit gracefully
4. WHEN MongoDB operations fail, THE System SHALL handle exceptions and provide clear error messages
5. WHEN cosine similarity calculations fail, THE System SHALL log the error and return an empty candidate list

### Requirement 13: Search Performance and Scalability

**User Story:** As a system administrator, I want efficient search performance, so that candidate matching remains fast as the user base grows.

#### Acceptance Criteria

1. WHEN performing similarity search, THE System SHALL load all user embeddings into memory in a single database query
2. WHEN calculating similarities, THE System SHALL use numpy arrays for vectorized operations
3. WHEN filtering results, THE System SHALL apply the 0.6 threshold before sorting to reduce computation
4. THE System SHALL complete candidate searches in under 2 seconds for up to 1000 users
5. THE System SHALL document performance characteristics and scaling limitations in code comments
