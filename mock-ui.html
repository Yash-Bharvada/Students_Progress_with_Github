🧪 Mock UI Testing Interface

Student Progress Tracker - Backend Testing Tool

🚀 Quick Start Guide

Welcome to the Mock UI Testing Interface! This tool allows you to test all backend functionality without a production frontend.

Testing Workflow:

  1. Configure Backend: Set your backend URL (default: http://localhost:8000)
  2. Login: Click "Login with GitHub" to authenticate via OAuth (or paste a JWT token for testing)
  3. Test Features: Based on your role (MENTOR or STUDENT), different sections will be available
  4. View Results: All API responses appear in the "Response / Results" section at the bottom

Role-Based Access:

  • MENTOR: Can enroll students, create repositories, view all metrics, and generate feedback for any student
  • STUDENT: Can save their own metrics, view their own data, and generate feedback for themselves

💡 Tip: Expand the help sections (marked with ℹ️) in each feature area for detailed instructions and examples!

👥 Student Enrollment MENTOR ONLY

This feature requires MENTOR role

ℹ️ How to Enroll Students

−

Step-by-Step Instructions:

  1. Enter the student's GitHub username (not their display name)
  2. Enter the student's email address
  3. Click "Enroll Student"
  4. The student will be created in the system and can now login via GitHub OAuth
  5. Click "Refresh List" to see all students you've enrolled

Role Requirements:

MENTOR only - Students cannot enroll other students

Example Values:

GitHub Username:
student1
Email:
student1@example.com

Important Notes:

  • The GitHub username must match the student's actual GitHub account
  • Once enrolled, students can login using the "Login with GitHub" button
  • The enrolled students list is fetched from the backend and shows all students you've enrolled
  • Each enrolled student will have the STUDENT role automatically assigned

📊 Contribution Metrics STUDENT ONLY

This feature requires STUDENT role

ℹ️ How to Save Contribution Metrics

−

Step-by-Step Instructions:

  1. Enter the Repository ID (get this from your mentor or from the repository list)
  2. Enter your Commit Count (number of commits you've made)
  3. Enter your Pull Request Count (number of PRs you've created)
  4. Enter your Issue Count (number of issues you've worked on)
  5. Enter your Consistency Score (0.0 to 1.0, representing how consistently you contribute)
  6. Click "Save Metrics"

Role Requirements:

STUDENT only - Students save their own metrics

Example Values:

Repository ID:
507f1f77bcf86cd799439011
Commits:
50
Pull Requests:
10
Issues:
5
Consistency Score:
0.85

Important Notes:

  • All counts must be non-negative integers
  • Consistency score must be between 0.0 and 1.0 (e.g., 0.85 means 85% consistency)
  • Metrics are automatically associated with your GitHub ID
  • You can update metrics by saving again with the same repository ID

GraphQL Mutation: saveContributionMetrics

Edit the mutation above. Changes will be used when you click "Save Metrics".

🤖 AI Feedback Generation

ℹ️ How to Generate AI Feedback

−

Step-by-Step Instructions:

  1. Enter the Repository ID
  2. For Students: Leave Student GitHub ID empty (feedback will be for yourself)
  3. For Mentors: Enter the Student GitHub ID to generate feedback for that student
  4. Click "Generate AI Feedback"
  5. View the quality score, strengths, issues, and suggestions in the response

Role Requirements:

  • STUDENT: Can generate feedback for themselves (Student GitHub ID not required)
  • MENTOR: Can generate feedback for any student (Student GitHub ID required)

Example Values:

Repository ID:
507f1f77bcf86cd799439011
Student GitHub ID (for mentors):
12345678

Feedback Components:

  • Quality Score: Overall quality rating (0.0 to 1.0)
  • Strengths: List of positive aspects of the contributions
  • Issues: List of areas that need improvement
  • Suggestions: Actionable recommendations for improvement

Important Notes:

  • AI feedback is generated based on contribution metrics and code analysis
  • Mentors must specify which student to generate feedback for
  • Students automatically get feedback for their own contributions

Leave empty if you're a student generating feedback for yourself

🎯 Candidate Search

ℹ️ How to Search for Candidates

−

Step-by-Step Instructions:

  1. Enter a job description in the text area
  2. Include specific skills, technologies, and requirements
  3. Click "Find Candidates"
  4. View matching candidates with their match scores and verified skills

Role Requirements:

Available to all authenticated users (both MENTOR and STUDENT)

Example Job Description:

Job Description:
Looking for a Python developer with FastAPI experience, strong database skills (PostgreSQL, MongoDB), and knowledge of GraphQL. Must have experience with REST APIs, authentication systems, and cloud deployment. Bonus points for Docker and CI/CD experience.

How It Works:

  • The system analyzes the job description to extract required skills
  • It matches students based on their verified skills from contribution history
  • Each candidate receives a match score (0.0 to 1.0)
  • Results are sorted by match score (highest first)

Result Fields:

  • Username: Student's GitHub username
  • Email: Student's contact email
  • Match Score: How well they match the job (0.0 to 1.0)
  • Verified Skills: List of skills verified through their contributions

Important Notes:

  • Be specific in your job description for better matches
  • Include both required and preferred skills
  • Skills are verified based on actual code contributions and metrics
  • If no candidates match, try broadening your search criteria

GraphQL Query: findCandidates

Edit the query above. Changes will be used when you click "Find Candidates".
